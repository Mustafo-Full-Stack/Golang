Домашнее задание: select, default в select и sync.WaitGroup

Лёгкие задачи

1. Создай два канала chan string: ch1 и ch2. Запусти две горутины: первая через 1 секунду отправляет в ch1 "из первого", вторая через 2 секунды отправляет в ch2 "из второго". В main сделай один select и напечатай то, что пришло первым.

2. Возьми задание 1 и сделай так, чтобы получить оба сообщения: оберни select в цикл for i := 0; i < 2; i++. Напечатай оба сообщения в том порядке, в котором они пришли.

3. Создай канал chan int. Запусти горутину, которая через 3 секунды отправит в него число 42. В main сделай select с двумя case: чтение из канала и <-time.After(1 * time.Second). Напечатай "Дождались: 42" или "Таймаут". Поменяй паузы местами и проверь оба варианта.

4. Создай пустой канал chan int (в него никто ничего не пишет). Сделай select с case <-ch и default, в default напечатай "Данных пока нет". Убедись, что программа не зависает.

5. Создай буферизированный канал make(chan int, 3). Через select с case ch <- i и default попробуй отправить в него числа от 1 до 5 в цикле. Если буфер полон — в default напечатай "Буфер полон, пропускаем число <i>". Сколько чисел попало в канал, а сколько пропустили?

6. Создай канал chan string с буфером 1 и положи в него одно сообщение. Напиши функцию tryRead(ch chan string), которая через select с default либо печатает прочитанное сообщение, либо "Пусто". Вызови её три раза подряд и посмотри на вывод.

7. Напиши функцию worker(id int, wg *sync.WaitGroup), которая через defer wg.Done() спит id * 100 миллисекунд и печатает "Воркер <id> закончил". Запусти 5 воркеров в цикле и дождись всех через sync.WaitGroup (Add до go, Wait в конце main).

8. Создай два канала chan int: even и odd. Запусти одну горутину, которая в цикле от 1 до 10 отправляет чётные числа в even, а нечётные в odd, и после цикла закрывает оба канала (через close). В main прочитай всё через select в цикле for и напечатай "чётное: N" или "нечётное: N". Подсказка: не забудь про v, ok := <-ch и про то, что закрытый канал читается всегда — когда оба закрыты, выйди из цикла.

9. Создай канал done chan struct{} и канал messages chan string. Запусти горутину, которая раз в 500 миллисекунд отправляет в messages строку "ping", а через 2 секунды закрывает done. В main в цикле for + select читай messages и печатай их, а при закрытии done выйди из цикла и напечатай "Конец".

10. Создай канал results chan int. Запусти 3 горутины (через WaitGroup), каждая отправляет в results своё число (1, 2, 3) после паузы. В main в отдельной горутине дождись wg.Wait() и закрой results. Основной поток читает results через for v := range results и печатает сумму всех чисел.

Задачи среднего уровня

11. Напиши функцию fastest(), которая запускает три горутины-"сервера" (каждая спит случайное время от 100 до 1000 миллисекунд через rand.Intn и отправляет в общий канал своё имя "сервер 1", "сервер 2", "сервер 3"). В main через select прочитай первый ответ из канала и напечатай, какой сервер ответил быстрее всех. Добавь в select ограничение: если никто не ответил за 500 миллисекунд — напечатай "Все сервера слишком медленные".

12. Напиши "очередь с отбрасыванием": канал tasks := make(chan int, 3) и горутина-потребитель, которая читает tasks и обрабатывает каждую задачу 300 миллисекунд (time.Sleep). В main в цикле от 1 до 10 с паузой 100 миллисекунд отправляй задачи через select с default. Если буфер полон — печатай "Задача <i> отброшена". В конце дождись потребителя через WaitGroup (для этого закрой tasks после цикла) и напечатай, сколько задач обработано, а сколько отброшено.

13. Напиши программу "проверка сайтов": срез из 5 названий сайтов. Для каждого запусти горутину (через WaitGroup), которая имитирует запрос — спит случайное время от 100 до 1500 миллисекунд и отправляет в канал results строку "<сайт> - OK". В main в цикле for i := 0; i < len(sites); i++ ставь select: либо читаем результат из results, либо срабатывает общий таймаут time.After(1 * time.Second) на весь запрос — тогда печатаем "Время вышло" и выходим из цикла. В конце выведи, сколько сайтов ответили вовремя. Подсказка: чтобы горутины не зависли на отправке, сделай канал буферизированным с размером len(sites).

14. Напиши функцию merge(a, b chan int) chan int, которая запускает горутину и объединяет два входных канала в один выходной: в цикле for + select читает из a и b и отправляет значения в выходной канал. Когда оба входных канала закрыты, закрывает выходной. Чтобы не крутиться вхолостую на закрытом канале, после обнаружения закрытия делай локальную переменную-канал равной nil (a = nil) — чтение из nil-канала в select никогда не сработает. В main запусти две горутины-генератора (первая шлёт 1, 2, 3, вторая 10, 20, 30), вызови merge и прочитай все 6 чисел через range.

15. Мини-проект "стоп-кран": запусти 3 воркера-горутины через WaitGroup. Каждый воркер в бесконечном цикле for + select: если пришёл сигнал из канала stop chan struct{} — печатает "Воркер <id> остановлен" и выходит (return); иначе (в default) печатает "Воркер <id> работает" и спит 400 миллисекунд. В main подожди 2 секунды, затем закрой stop (close(stop)) и дождись, пока все воркеры завершатся (wg.Wait()). Напечатай "Все воркеры остановлены".

Что считается сделанным: используются только select, default, time.After, каналы и sync.WaitGroup — без sync.Mutex и без пакета context (он будет позже); wg.Add(1) вызывается до go, а wg.Done() — через defer первой строкой в горутине; sync.WaitGroup передаётся в функции только через указатель (*sync.WaitGroup); каждая программа запускается минимум 2-3 раза, и ты можешь объяснить, почему вывод может отличаться; при желании проверь решения командой go run -race . и убедись, что DATA RACE не появляется.
