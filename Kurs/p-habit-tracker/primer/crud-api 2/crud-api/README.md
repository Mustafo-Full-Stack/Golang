# crud-api

## Запуск

1. Скопировать `.env.example` в `.env`, задать `JWT_SECRET` и заполнить `POSTGRES_*`.
2. Применить миграции:

```
psql "$DSN" -f migrations/001_create_users.sql
psql "$DSN" -f migrations/002_posts.sql
```

3. `go run ./cmd/api`

## Токены (JWT)

`/auth/login` возвращает пару токенов, подписанных HS256 ключом `JWT_SECRET`:
- `access_token` — передаётся в `Authorization: Bearer <token>`, живёт `ACCESS_TOKEN_TTL` (по умолчанию `15m`);
- `refresh_token` — живёт `REFRESH_TOKEN_TTL` (по умолчанию `720h`), как access-токен не принимается.

В токене лежат `user_id`, `type` (`access`/`refresh`) и стандартные `iat`, `exp`. Токены нигде не хранятся — сервер только проверяет подпись и срок. Отозвать токен до истечения срока нельзя, поэтому ручки logout нет: клиент просто удаляет токен у себя.

### Фича: хранение токенов в Redis

Следующий шаг — хранить выданные токены в Redis. Тогда сервер сможет их отзывать, и появятся logout и `/auth/refresh`.

**Сам токен в Redis не кладём — только его хеш.** Если базу украдут, хеши бесполезны: из хеша нельзя получить токен и войти под пользователем. Расшифровывать токен серверу не нужно: чтобы проверить его, достаточно посчитать хеш ещё раз и сравнить. Поэтому вместо шифрования используем хеш SHA-256 (`crypto/sha256`). Ключ шифрования пришлось бы где-то хранить, а у хеша ключа нет.

Ключи в Redis:

| Ключ | Значение | TTL |
|---|---|---|
| `refresh:<sha256(refresh_token)>` | `user_id` | `REFRESH_TOKEN_TTL` |
| `blacklist:<sha256(access_token)>` | `1` | сколько access-токену осталось жить |

TTL ставим равным сроку жизни токена: Redis сам удалит ключ, когда токен истечёт, и чистить мусор вручную не придётся.

Как это работает:
- **login** — выдаём пару токенов и сохраняем `refresh:<hash>` → `user_id`;
- **refresh** — проверяем подпись refresh-токена и наличие `refresh:<hash>` в Redis, удаляем старый ключ и выдаём новую пару (refresh-токен одноразовый);
- **logout** — удаляем `refresh:<hash>` и кладём access-токен в `blacklist:<hash>` до конца его срока;
- **authMiddleware** — кроме подписи и срока проверяем, что access-токена нет в `blacklist`.

Что понадобится в коде: метод `Revoke` в `token.Manager`, реализация менеджера на Redis (подключение уже есть в `pkg/db/redis`) и переменные `REDIS_*` в конфиге.

## Логирование

Логи пишутся через `slog` в stdout с уровнем `LOG_LEVEL` (по умолчанию `info`):
- `ENVIRONMENT=local` — читаемым текстом;
- иначе — JSON.
