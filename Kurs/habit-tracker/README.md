# Трекер привычек

REST API на Go 1.22+ и PostgreSQL. Реализованы регистрация, вход с выдачей JWT, защищённые маршруты привычек и отметки выполнения.

Спецификация API: [docs/openapi.yaml](./docs/openapi.yaml). Её можно открыть в Swagger Editor или импортировать в Postman.
Описание слоёв и бизнес-правил: [docs/architecture.md](./docs/architecture.md).

## Запуск

1. Создайте базу данных PostgreSQL, если её ещё нет.
2. Скопируйте `.env.example` в `.env` и задайте свои значения.
3. Загрузите настройки в текущую оболочку:

   ```sh
   set -a
   . ./.env
   set +a
   ```

4. Проверьте, что PostgreSQL доступен на адресе и порту из `.env`. Если ваш PostgreSQL слушает `5433`, укажите `POSTGRES_PORT=5433`.
5. Примените миграции по порядку:

   ```sh
   PGPASSWORD="$POSTGRES_PASSWORD" psql \
     -h "$POSTGRES_HOST" -p "$POSTGRES_PORT" \
     -U "$POSTGRES_USER" -d "$POSTGRES_DB" \
     -f migrations/001_create_users.sql

   PGPASSWORD="$POSTGRES_PASSWORD" psql \
     -h "$POSTGRES_HOST" -p "$POSTGRES_PORT" \
     -U "$POSTGRES_USER" -d "$POSTGRES_DB" \
     -f migrations/002_create_habits.sql
   ```

6. Запустите сервер в первом терминале и оставьте его работающим:

   ```sh
   go run ./cmd/api
   ```

   При успешном запуске появится сообщение `http server listening on :8080`.
   Запросы `curl` или коллекцию Postman запускайте во втором терминале.

Приложение читает настройки из переменных окружения и самостоятельно не загружает файл `.env`.

## Запуск в Docker

Скопируйте `.env.example` в `.env`, задайте секрет JWT и пароль PostgreSQL, затем выполните:

```sh
make up
```

Docker Compose дождётся готовности PostgreSQL, применит SQL-файлы из `migrations/` при первом создании тома базы и запустит API. Откройте `http://localhost:8080`. Для просмотра логов используйте `make logs`; `make down` останавливает контейнеры и сохраняет данные, а `make reset` удаляет том базы, чтобы миграции применились заново.

Для локального запуска Go-приложения используйте `make db`, загрузите настройки `.env` в текущую оболочку (`set -a; . ./.env; set +a`), затем выполните `make run`.

## Проверка через curl или Postman

Импортируйте JSON коллекции Postman, выберите её и запустите запросы по порядку. Запросы входа автоматически сохраняют токены, а создание привычки сохраняет её ID.

Если `curl` отвечает `Failed to connect to localhost port 8080`, HTTP-сервер не запущен. Убедитесь, что команда `go run ./cmd/api` всё ещё работает в первом терминале и что перед запуском были загружены настройки из `.env`. Если приложение завершилось с ошибкой, прочитайте её там: без `JWT_SECRET` оно не запустится, а при недоступной базе не сможет создать пул соединений.

`curl: (7)` возникает до отправки HTTP-запроса, поэтому в этом случае проблема ещё не в токене или маршрутах. После запуска сервера ошибки API будут возвращаться с HTTP-статусом и JSON-ответом.

## Эндпоинты

- `POST /sign-up` — регистрация: `{"name":"Имя","email":"user@example.com","password":"пароль"}`, ответ `201 {"id":1}`.
- `POST /login` — вход: `{"email":"user@example.com","password":"пароль"}`, ответ `200 {"token":"..."}`.
- `POST /habits` — создать привычку: `{"name":"Читать"}`, требуется токен.
- `GET /habits` — список своих привычек, требуется токен.
- `POST /habits/{id}/check` — отметить привычку за сегодня, требуется токен.
- `GET /habits/{id}/checks` — список отметок привычки по дням, требуется токен.

Для защищённых маршрутов передавайте JWT в заголовке `Authorization: Bearer <token>`.

## Ошибки

- `400` — неверный формат запроса или обязательные поля не заполнены.
- `401` — отсутствует или недействителен токен; либо неверны email или пароль.
- `403` — привычка принадлежит другому пользователю.
- `404` — привычка не найдена.
- `409` — пользователь уже существует или привычка уже отмечена сегодня.
